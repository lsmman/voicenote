# Supabase / Vercel setup

1. Create a Supabase project. Copy its project URL and anon key (not the service-role key) into the matching variables in the root `.env.example`, saved locally as `.env`.
2. Run `migrations/0001_init.sql` in the project's SQL Editor once, or apply it with your existing Supabase migration workflow. It creates five tables, owner-only RLS, two invoker-rights sync RPCs, and the private `audio` bucket. IDs are text to preserve the domain's string IDs; ownership IDs are auth UUIDs. JSON item timestamps use `at_ms`. `summaries.summary` stores the contract's seekable items rather than the earlier design's `summary_md`.
3. Under Authentication → Providers, enable Email and email magic-link sign-in. Keep the email template's confirmation URL link. Under Authentication → URL Configuration, set Site URL to `https://YOUR_PROJECT.vercel.app`, and allow that origin, its trailing-slash form, `voicenote://`, and `voicenote:///` (the native root callback). Add only the development/preview origins you use. The native app already declares the `voicenote` scheme; use a development or production build for stable callbacks.
4. Deploy this repository to Vercel with the checked-in `vercel.json`. Set `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY` for the web build. Set `SUPABASE_URL`, `SUPABASE_ANON_KEY`, and `ANTHROPIC_API_KEY` for the server function. Keep `EXPO_PUBLIC_API_BASE` empty for same-origin web calls; set it to the HTTPS Vercel origin when building the native app. Public Expo variables are embedded at build time, so rebuild after changing them.
5. The app should pass native initial/warm login deep links to `handleAuthRedirect(url)`; web URL sessions are automatically detected by Supabase. `useSession()` observes the session and unsubscribes on unmount. Code and token-fragment redirects are both supported.
6. Smoke-test with two separate users: each can push/pull their own notes and upload/sign their own audio; neither can access the other's rows or storage paths. Call `/api/summarize` with a valid access token; verify missing/invalid tokens return 401. No service-role key is required.

`pushNote` atomically replaces segments/memos and upserts or removes the summary using `sync_push_note`. Concurrent pushes serialize on the note; the last successful push wins. Detail reads aggregate inside one SQL snapshot so 3-hour transcripts are not clipped by PostgREST's default row cap. Audio upload returns a path only after Storage confirms it. The current `SyncService` contract has no chunk-metadata push/pull methods: `audio_chunks` is prepared, but callers cannot yet discover remote chunks through this interface. Device-local file paths must not be reused on another device.

The summarize function accepts at most 4 MiB of JSON, verifies Supabase auth, and streams Claude internally before returning one validated JSON response. It allows 300 seconds; ensure the Vercel plan permits that duration. Helpers and tests live in underscore-prefixed API directories so Vercel does not expose them as endpoints. Live database policies, email delivery, native deep links, and deployment require project credentials and are separate from offline unit tests.
