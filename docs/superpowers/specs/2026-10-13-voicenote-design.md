# voicenote 설계 (1단계)

작성: 2026-10-13

## 목표

장시간 녹음을 받아 적는 음성 노트 앱. 핵심은 세 가지다.

1. **장시간 녹음이 끊기거나 유실되지 않는다** — 3시간 이상, 모바일은 화면 잠금 상태에서도.
2. **녹음 중 메모를 남긴다** — 메모는 녹음 시각에 묶여 재생바 마커가 된다.
3. **말한 내용을 정확히 전부 글로 남긴다** — 기기 안 Whisper 모델로 전사하고, 요약·키워드·할 일을 뽑는다.

## 확정된 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 클라이언트 | Expo (React Native) 하나로 iOS·Android·Web | 웹과 모바일을 동등하게. 모바일 백그라운드 녹음은 네이티브가 필요 |
| 배포 | Vercel: Expo 웹 빌드 + `/api/summarize` 함수 | 사용자 지정 |
| 전사 | 기기 안 Whisper — 모바일 `whisper.rn`, 웹 transformers.js + WebGPU | 사용자 지정 (자체 모델, 서버 비용 0) |
| 기본 모델 | `large-v3-turbo` 양자화, 설정에서 `small` 선택 가능 | small 이하는 한국어 정확도가 낮음 |
| 요약 | Claude API를 Vercel 함수 경유로 호출 | 품질 우선. 전사문만 서버로 나감 |
| 동기화·로그인 | Supabase (Auth + Postgres + Storage) | 폰에서 녹음한 노트를 웹에서 열람. Expo SDK 있음 |
| 화자 분리 | 2단계로 미룸. 1단계는 문단별 수동 화자 지정 | 온디바이스 화자 분리 도구가 미성숙 |

기존 기획 메모의 "Next.js 웹앱" 결정은 이 문서로 대체한다.

## 구조

```
Expo 앱 (iOS / Android / Web)
 ├─ recorder     녹음 → 30초 청크 → 기기 디스크 → 업로드 큐
 ├─ transcriber  청크 큐 → 기기 안 Whisper → 구간(segment) 저장
 ├─ notes        메모·북마크, 노트 편집, 로컬 DB
 └─ sync         Supabase와 노트·메모·전사문·오디오 동기화
        │
        ├──► Supabase: Auth, Postgres(노트 데이터), Storage(오디오 청크)
        └──► Vercel /api/summarize: 전사문 + 메모 → Claude → 요약·키워드·할 일
```

각 모듈은 플랫폼 차이를 인터페이스 뒤에 숨긴다. `recorder`와 `transcriber`는 네이티브 구현과 웹 구현을 따로 두고, 같은 인터페이스를 쓴다.

## 데이터 모델

- **note**: id, user_id, title, created_at, duration_ms, status (`recording` | `transcribing` | `summarizing` | `done` | `error`), model_name
- **audio_chunk**: note_id, seq, start_ms, duration_ms, local_path, remote_path, uploaded_at, transcribed_at
- **segment**: note_id, start_ms, end_ms, text, speaker_label (nullable, 수동 지정), edited (bool)
- **memo**: note_id, at_ms, text, kind (`memo` | `bookmark`)
- **summary**: note_id, summary_md, keywords[], todos[], created_at

모든 시각은 녹음 시작 기준 밀리초. 일시정지 구간은 시간축에서 뺀다.

## 녹음 안정성

1. **청크 단위 즉시 저장.** 30초마다 독립 재생 가능한 파일(AAC/m4a, 웹은 webm/mp4)로 디스크에 쓴다. 앱이 죽어도 손실은 마지막 청크 이내.
2. **세션 저널.** 녹음 시작 시 로컬 DB에 note 행을 `recording` 상태로 만들고, 청크마다 행을 추가한다. 재실행 시 `recording`인 노트를 찾아 복구를 제안한다.
3. **백그라운드 유지.**
   - iOS: `UIBackgroundModes: audio`. 오디오 세션 인터럽트(전화 등) 뒤에는 자동 재개하고, 끊긴 구간은 노트에 표시한다.
   - Android: 마이크 타입 포그라운드 서비스와 상시 알림.
   - Web: Wake Lock을 쓴다. 모바일 브라우저에서는 "화면을 끄면 녹음이 멈출 수 있음"을 안내한다.
4. **업로드 큐.** 청크를 순서대로 Supabase Storage에 올린다. 업로드 확인 후에만 `remote_path`를 기록하고, 로컬 파일은 노트 완료와 업로드 완료가 둘 다 확인된 뒤에만 지울 수 있다. 오프라인이면 지수 백오프로 재시도한다.
5. **감시.** 마이크 트랙 종료, 10초 이상 레벨 0, 남은 저장공간 1GB 미만이면 경고 배너를 띄운다.
6. **파일 가져오기.** 기존 오디오 파일(m4a, mp3, wav, webm)을 가져오면 30초 청크로 나눠 녹음과 같은 업로드·전사 경로를 탄다.
7. **웹 녹음기.** MediaRecorder `timeslice` 5초. 조각을 IndexedDB에 모아 30초 청크로 묶는다. 20분마다 레코더를 재시작해 파일 길이 메타데이터 문제를 피한다.

## 전사

1. 청크가 디스크에 저장되면 전사 큐에 들어간다. 녹음 중에도 큐를 처리해 실시간 자막처럼 보여 준다.
2. 청크 앞에 직전 청크의 마지막 1초를 붙여 전사하고, 겹친 구간의 중복 문장은 시각 기준으로 제거한다.
3. 결과는 segment(시작·끝 시각, 텍스트)로 저장한다. 언어는 `ko` 고정, 이전 청크의 마지막 문장을 프롬프트로 넘겨 문맥을 잇는다.
4. 기기가 느려 큐가 밀리면 녹음 뒤에도 계속 처리하고, 목록에 진행률을 보여 준다. 모바일 백그라운드에서 추론이 멈추면 포그라운드 복귀 시 이어서 처리한다.
5. 모델은 첫 사용 시 내려받는다. 다운로드는 이어받기를 지원하고, 체크섬으로 검증한다. 모델이 없는 상태에서도 녹음은 가능하고, 전사는 대기한다.
6. 노트 상세의 "전사 다시 하기"로 다른 모델을 골라 전체를 재처리할 수 있다. 사용자가 고친 segment는 덮어쓰기 전에 확인을 받는다.

## 요약

- 전사가 끝나면 `/api/summarize`에 전사문과 메모를 보낸다. 메모와 북마크는 "사용자가 중요하다고 표시한 지점"으로 프롬프트에 포함한다.
- 응답은 요약(마크다운), 키워드, 할 일 목록이다. 요약의 각 항목에는 근거 segment의 시각을 붙여, 누르면 그 지점으로 이동한다.
- 함수는 Supabase JWT로 사용자를 확인한다. API 키는 Vercel 환경 변수로만 둔다.
- 전사문이 모델 컨텍스트를 넘으면 구간별로 요약한 뒤 합친다. 정확한 모델 ID와 한도는 구현 계획 단계에서 정한다.

## 화면

1. **노트 목록**: 검색(제목·전사문), 최신순 정렬, 상태 배지, 녹음 시작 버튼.
2. **녹음 화면** (목록에서 "파일 가져오기"도 제공): 큰 타이머, 레벨 미터, 실시간 자막, 하단 메모 입력(Enter로 추가), 북마크 버튼, 일시정지·종료, 경고 배너.
3. **노트 상세**: 상단 고정 플레이어. 재생바에 메모·북마크 마커가 있고, 배속은 0.5–2×. 탭은 [요약 | 전사문 | 메모].
   - 전사문: segment를 누르면 그 지점부터 재생되고, 길게 누르면 편집하거나 화자를 지정한다. 재생 중인 문장을 강조한다.
   - 내보내기: txt, md.
4. **설정**: 전사 모델 선택·다운로드·삭제, 저장공간 사용량, 계정.
5. **로그인**: Supabase 이메일 매직 링크.

## 오류 처리

| 상황 | 동작 |
|---|---|
| 앱 강제 종료·크래시 | 재실행 시 `recording` 노트 복구 제안. 저장된 청크까지 살림 |
| 마이크 권한 거부 | 녹음 시작 전 차단, 설정 이동 안내 |
| 전화·다른 앱의 오디오 인터럽트 | 자동 재개 시도, 끊긴 구간 표시 |
| 저장공간 부족 | 1GB 미만에서 경고, 200MB 미만이면 녹음을 안전하게 종료 |
| 오프라인 | 녹음·전사는 계속. 업로드·요약은 대기 후 재시도 |
| 모델 다운로드 실패 | 이어받기 재시도. 그동안 녹음만 진행 |
| 요약 API 실패 | 노트는 `done`으로 두고 요약 탭에 재시도 버튼 |

## 테스트

- **단위**: 청크 저널·복구, 업로드 큐 재시도와 순서, 겹침 구간 중복 제거, 일시정지를 반영한 시간축 계산.
- **통합**: 짧은 오디오 fixture로 전사 → segment 저장 → 요약 호출(모의) 흐름.
- **실기기 수동 검증**: iOS·Android 각각 화면 잠금 상태로 3시간 녹음 → 청크 누락 0, 재생 길이 일치. 녹음 도중 앱 강제 종료 → 복구 확인.
- **정확도**: 한국어 회의 샘플 30분과 정답 전사본으로 CER을 잰다. `small`과 `large-v3-turbo`를 비교해 기본값 결정을 검증한다.

## 2단계 이후 (이번 범위 아님)

자동 화자 분리(sherpa-onnx 검증 후), 공유 링크, 다국어, 키워드 부스팅(사용자 사전).

## 위험

- **기기 성능**: 구형 기기에서 `large-v3-turbo`가 실시간보다 느릴 수 있다. 큐가 밀리는 것은 허용하되, 녹음 품질에는 영향이 없어야 한다(녹음과 추론은 분리).
- **웹 WebGPU 미지원 브라우저**: WASM으로 대체하면 느리다. small 모델 권장 안내.
- **Expo Go 불가**: `whisper.rn`은 네이티브 모듈이라 개발 빌드(EAS)가 필요하다.
